Animal Shelter Dashboard

A progression from a notebook-based dashboard to a modular application with explainable candidate ranking and reliable relational storage.

The starting point

The original CS 340 application used Python, JupyterDash, and MongoDB to filter shelter records and display a table, breed chart, and location map. Its tightly connected components, embedded configuration, and dependence on the original database created opportunities to improve maintainability and reliability.

The original database environment is unavailable. The enhanced application uses clearly labeled synthetic records and can run locally with SQLite.

Three connected enhancements

  1. 01

    Software Design and Engineering

    Separated configuration, data access, application logic, and presentation into a standalone Dash application.

    30 tests at this stage

How the final application works

Settings choose a data repository. The application validates query choices, retrieves matching records, and updates the table, chart, and map. In SQLite mode, scores and ranks are calculated across the matching records before a page is returned. Only that page is transferred to the browser.

Trade-offs and boundaries

Ranking provides more information than strict filtering but adds processing and memory costs. Database pagination reduces transferred rows; it does not eliminate the cost of ranking the matching set. The weights illustrate preferences and are not validated predictions of rescue suitability.

SQLite provides a portable local demonstration. Production authentication, authorization, concurrency, and deployment require additional work. The index experiment measures one query pattern on 20,000 synthetic records.
